Talk to the owner in Croatian; code, commits, code comments and all UI text in English.

## Stack and infrastructure
- React 19 + Vite 7 (migrated from CRA on 2026-11-07), react-router 7, plain CSS.
- Supabase project `ShiaiFlow-db-v2` (ref `baxyawzwfpkrylprztad`, eu-west-1). Free tier: auto-pauses after ~1 week idle.
- Netlify site `shiaiflow-frontend` → app.shiaiflow.com, auto-deploy from `master`. `shiaiflow.com` is a separate landing site.
- Env: `.env.local` with `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY` (old `REACT_APP_*` names still accepted via `envPrefix`).
- Run: `npm run dev` (http://127.0.0.1:3000), `npm run build` (→ `build/`), `npm run test:logic` (node:test, no deps).

## Domain rules (ported from the DP HKS 2026 Excel system — do not change silently)
- Pool size 1 = direct KO; advancing 0 = pools only. KO code = `K` + pools (2 digits) + advancing, e.g. K052.
- KO slots: `0P1`/`0P2` = winner/runner-up of pool P, `Wnn` = winner of KO match nn. First of a pair is AKA (red).
- Shiaijo plan (owner, 2026-11-07, `courts.js`, page `/tournament/:id/shiaijo`): director picks 1–6 courts, then the courts of each category (`categories.shiaijos`, e.g. Junior A 1+2, Junior B 3+4); category order = order on each court. A pool never splits across courts — whole pools are spread over the category's courts by fight count; KO bracket parts per court, final on the first court. Options: KO on other courts (`categories.ko_shiaijos`, final on the first KO court); central courts (`tournaments.central_shiaijos`); finals, or semifinals and finals, of all categories at the end of the tournament on the central courts (`tournaments.end_block`, fights flagged `matches.end_block` for the queue). Later: big pools (>3) may move single fights to another court to use idle time.
- Bracket editor (`/tournament/:id/brackets`, `bracketEdit.js`): drag a slot onto another (pointer events, mouse + touch) or click and type P2.1 / W03 / #5; moving a W slot moves that fight, or drag a whole fight by its head onto a slot / fight of another (`moveFight`: F-1 into F-3 instead of F-4, the displaced place takes the old spot), fights renumber only when a W ref would point forward. Same-half of a pool = warning, structure errors block saving. Saved to `categories.ko_template` + `ko_template_edited`; used by the draw, kept on undo; after the draw KO fights are rebuilt (refused once a KO fight started). Excel variants (`KO_VARIANTS`) offered as presets.
- Fight plan (`/tournament/:id/fights`): by category (pools, then KO) and by shiaijo (whole tournament in order, estimated start; end-of-tournament block after every court finished). Court per fight editable (`matches.court_manual`, plan changes skip it; "back to plan" resets).
- Access (owner, 2026-11-07): home page (before login) lists published tournaments with the ways in. Owner = main account, everything. One PIN per tournament (`tournament_pins`, RPC `claim_tournament`, anonymous sign-in enabled in Supabase Auth); the door decides the role: Editor + PIN → organizer (only after the owner publishes; edits before the start, Manage after), Table + PIN → scorer (only while running; scoretable, picks a shiaijo). Joining via the other door switches the role. Only the owner publishes / hides (trigger `only_owner_publishes`). Public (`is_public` = published by the owner): `/t/<tournament>` shows setup, entries (also while registration is open), draw, schedule, live results; "who are you" (no password, localStorage) → your next fight. Competitors register with a form (RPC `public_register` / `public_register_team`), no approval; owner/editor edit or remove entries. Registration closes by `registration_deadline` or by hand (`registration_open`). Teams per setup: `team_signup` = with_competitor (name a new team or pick one) or team_first (team picks members from registered competitors); `multi_team` allows one competitor in teams of different categories.
- Category rules (owner, 2026-11-07; `eligibility.js`, SQL `private.ineligible_reason`): gender, age by birth year (tournament year − birth year), grade range (mudan −7, 6 kyu −6 … 1 kyu −1, 1 dan 1 … 8 dan 8). Public form asks gender / birth year / grade (+ optional email → `competitor_contacts`, organizers only) and ticks every allowed category; forbidden ones are greyed out and refused by `public_register`. Organizer entries only warn. No members-only rule for now (later: federations with a member list).
- Draws confirmed (`tournaments.draws_confirmed`, owner can reopen): editors stop changing the setup (bracket editor, undo draw, tournament data); entries still change and the draw is adjusted with as little change as possible — replace a no-show in the same place, add a late entry to a short pool (that pool's fights rebuilt), withdraw (before the pool started: out + rebuild; after: remaining fights fusen to the opponents). Later: email affected competitors about changes.
- Running (owner, 2026-11-07; `run.js`, `runApi.js`, pages Manage / ScoreInput / JoinCourt):
  - Start button (`StartTournament.jsx`) in Registration (below the check-in) and Manage, with a readiness table per category (drawn, present x / y); confirm dialog. Manager (owner/organizer) starts the tournament → `matches.court_seq` freezes the order per court; manager does admin changes and corrections (reopen a finished fight) — scorers cannot.
  - One scorer per shiaijo, several screens in parallel (realtime); the table picks its shiaijo.
  - Timer built in (hajime / yame, stops on every point; shared via `timer_elapsed_ms` + `timer_started_at`); `tournaments.use_timer` off = separate timekeeper, scorer presses "Time up".
  - Scoring letters: M K D T, I = ippon from opponent's 2nd hansoku, HH = hantei, OO = fusen-gachi; HH and OO are a 2–0 win. Two ippons end a fight; in encho / ipponshobu the first point wins.
  - Per category, separately pools / KO: pool tie → hikiwake or encho (`pool_tie`), encho length (null = until a point), hantei after encho. KO never draws.
  - Starting a fight further down the queue moves the skipped ones below it. KO fights may start as soon as both fighters are known (no waiting for all pools).
  - After a pool: rank (Excel criteria); tie for a place that matters → ipponshobu `F-Pn.D` right after on the same court; two ties → replay message for the manager; places → KO slots; KO winners move on.
  - Team matches at the table (owner, 2026-11-19; `team.js` teamMatchStep / defaultLineup / lineupProblems / boutRows, `TeamLineup.jsx`, runApi confirmLineups / startBout / finishBout / addDaihyosen): the table works as for individual fights — first a lineup step (warning: lineups first; the table enters both orders from the papers, prefilled with the team's previous match order, else the registration order; ticks "both handed in", Confirm → one `bouts` row per position), then the position bouts one after another with the same buttons (a bout may end hikiwake; no encho), shared timer reset per bout. Empty positions only where allowed (3-team chuken, 5-team jiho / fukusho; a short team gets them proposed empty) → fusen for the other team at once. All bouts done → more bout wins → more ippons → else daihyosen (KO always, pools when `pool_tie` = 'encho', pool ipponshobu between teams = daihyosen only); the table picks one fighter per team (default taisho), fought as encho (first point; daihyosen time / hantei rules). Then "Finish team match". Managers: "Correct: reopen <position>". Team pools rank by team results (`teamMatchSummary`: winner, ippons of all bouts; whole-match fusen = 2 per position). Lineups shown publicly only after the table confirms.
  - Team lineups step 2 (later, memory team-lineups-online): online lineup / daihyosen pick by captains with a team PIN (setup toggle); one fighter twice (setup option).
  - Fight plan: tournament start time → clock times; Print = one shiaijo per page.
- Pool standings (owner, 2026-11-20; `poolView.js` poolStandings / fightMarks, `PoolStandings.jsx` + `usePoolData`): same ranking as when a pool finishes (category's ranking criteria), # / name / W L D / ippons + −, bold = through to the KO, ipponshobu / replay note. Public Draw tab: standings replace the member lists once a category's pools started (live); the public Live tab (shiaijos across the screen, each ≤ 520px, 2–3 per row) adds, below the courts, each started category's standings and KO bracket; finished KO fights show the points per side, winner bold, loser faded (`KoBracket` `results`). Manage: "Pool standings" card (`g-standings`) with Fights under each pool and Correct = reopen the fight on its shiaijo (disabled while another fight runs there) — results change only through the fights. Scoretable: a button per pool fought on that shiaijo → standings popup; its Next / Finished lists sit in two equal columns, names red / black by side, Finished shows the points and ▲ per side (OO, HH, X; teams wins (ippons)).
- Court display screens (owner, 2026-11-19; `CourtDisplay.jsx`, `/<link or /t/id>/court/<n>`, links in Manage): monitor next to each shiaijo, anyone with the link, no navbar, realtime. Full-width bands: last result; the fight in progress (each fighter in one row — name, hansoku ▲ right by it, points from the name towards the middle; only the first point of the fight circled (`firstPointSide`); white and red halves meet, X = hikiwake / E = encho in a white circle on the seam; no aka/shiro labels, no clubs); the next 3 fights with fight labels. NO timer (not allowed on the court display). Sized for a standard 16:9 TV read from about 10 m (nothing below ~2vw; name on two lines: surname, first name). Team matches: last / next = team against team (last: bout wins, ippons in brackets); in progress = team names with wins / ippons on the seam, then one row per position (3 or 5 + daihyosen; `teamBoard` in team.js; running bout outlined, later ones dimmed, position pill on the seam, replaced by a white X / E circle for a hikiwake / encho bout) — only once every position of both lineups is in `bouts` (lineups are written after both teams confirm), before that team against team. Updates by realtime (≈1 s after the scorer's click), plus a refresh every 30 s if realtime drops; keeps the screen awake (Wake Lock) and hides the pointer after 3 s. The next fight shows ("next fight") as soon as the current one is finished. Shiro left, aka right by default (as the shinpan see it); ⇄ Sides swaps per monitor (localStorage).
- Accounts (owner, 2026-11-08; SignupPage, ProfilePage, `/admin/accounts`): Individual (no verification, tournaments shown as PERSONAL tournament), Dojo, Federation (national/regional or continental). Dojo / federation: official email, city, country (full list via Intl), website, responsible person (name required, email optional); verified by the app admins (`app_admins`, `users.verified_at`) — until then everything except publishing the signup and starting a tournament (trigger `require_verified_organizer`). Kind change only via RPC `change_account_kind`: individual → dojo/federation = verification again; dojo/federation → individual = `needs_review`, admins approve again, tournaments lose the organization name. Name and website of a verified organization change only through the admins.

  - Category templates offered by the app only (Junior A ≤14, Junior B 15–18, Kyu W/M, Dan W/M, Team juniors ≤18, Team adults); a template is a starting point, everything editable incl. name; "Add new" for an empty one. No user-saved templates; copy the categories from an earlier tournament (own, or any public one). No abbreviations.
  - Part 1 = signup rules, each on/off (off = no limit), combined: age (organizer picks: by birth year or exact age on the tournament day → needs date of birth), gender (on = men and women separate), grade range; competitor may enter every category they qualify for unless the organizer allows only one. No per-club / total limits, no fee for now.
  - Teams: 3+1 or 5+2 (positions senpo, (jiho, chuken, fukusho,) taisho + reserves); organizer chooses same-dojo-only (e.g. national championships) or mixed; optional per-position rules (age / gender / grade, e.g. youngest category as senpo, fixed order); off = team list handed in at the tournament.
  - Step 2 built (`FightRules.jsx`; `splitPools`, `thirdPlaceFight` — L<sf> codes, fight no = final + 1, queued before the final on its court; `fightSeconds(category, phase, round)`, `koRound`, `koRoundLabel`; `scoringOptions` — ippon-shobu: first point wins, fusen/hantei = 1–0). Pool-of-4 minimum-fights format shown greyed out until the owner works out the rule.

- Setup guide (owner, 2026-11-20; `guide.js` tournamentPhase / createSteps / phaseSteps, `GuidePanel.jsx`): a thin line on the right of the organizer's pages (dashboard, create, tournament pages except the scoretable; on small screens only the current hint at the bottom) with only the current phase's steps — one word each, past steps almost invisible, only the hint of the first open step stands out left of the line; clicking jumps to the page and flashes the place (`id="g-…"` anchors). Phases create/setup → signup → draw → register → start → live → finished → past, worked out from the tournament's state; the current phase is shown only in the overview, next to the tournament picked on the dashboard (`useTournamentPhase`, `PhaseLabel`). The Create form feeds it while typing (`useGuide().setCreate`). Hidden per device with ✕ (`sf-guide-off`).
- Live updates (owner, 2026-11-19): screens listen only to their own tournament (`subscribeFights(tournamentId, onChange, wait)` → broadcast channel `run:<id>`, filled by DB triggers), bursts coalesced (scoretable 150 ms, display 300 ms, Manage 500 ms, public 1 s); on a change only fights / points / bouts are refetched, the rest on a slow refresh (display 30 s, public 60 s). Images are kept small (icons ~2× their shown size, background JPEG).
- Formats (owner, 2026-11-18): European everywhere — 24-hour time, day before month (`format.js`, en-GB; own fields `EuInputs.jsx`: TimeInput HH:MM, DateInput DD.MM.YYYY with the browser's calendar, DateTimeInput) because native time inputs follow the computer locale (AM/PM).
- Team ties (owner, 2026-11-18): bouts in a team match may be hikiwake; team match tied on wins and ippons → pools: draw or daihyosen (`pool_tie` 'hikiwake' / 'encho'), KO: always daihyosen; daihyosen tie rule + "Last rounds" apply to the daihyosen. A new category takes the fight rules (not times / pools) of the first category of its kind; "Same as" copies all fight settings of another category.
- Draw vs presence (owner, 2026-11-18): the draw is made days before and takes every registered entry; check-in ("present") happens on the day in Drawings → Adjust the draw (or Registration). Registration stays open for presence and walk-ins after the draw (remove / strength locked; cancelled category fully locked). Absentees are replaced or withdrawn there; a walk-in is added in Registration and then replaces a no-show or fills a short pool — full flexibility. Shiaijo plan and estimates count registered entries.
- Labels (owner, 2026-11-07): bracket slots shown as P1.1 (pool 1, 1st), P4.2, W05 (winner of fight 5), L04 (loser of fight 4, future second-chance bracket), #5 in a direct KO. Fights: F-P1.1 = pool 1 fight 1 (ipponshobu F-P1.D), KO fights F-1, F-2 … (`matches.label`).
- Pool ranking (Excel order): wins ↓, losses ↑, draws ↓, ippons scored ↓, ippons conceded ↑. Head-to-head NOT used by default.
- Pools: pool count = ceil(entries / pool size) as in the Excel, but sizes are even (7 by 3 → 3+2+2, `splitEvenly`). Organizer can swap/move entries in the draw preview before saving (`drawFromPools` recomputes matches/KO; seed is then null).
- Draw placement (owner, 2026-11-07, `placement.js`), every rule "if possible": strength tier per entry (`entries.tier`: 1 last year's champion, 2 runner-up, 3 third place, 4 strong, 5 medium, 6 weaker, null not rated). Priority: (1) tiers 1–3 in pools whose winners meet no earlier than the semifinal (1 vs 2 preferably only in the final); (2) same-club entries apart (direct KO: first matches), swapping within the same tier; (3) tiers 4–6 spread evenly — dropped if needed to separate clubs. 40 attempts from the seed, best kept; leftovers shown as warnings for a minimal manual fix. Excel K052 cannot keep 4 top entries apart until the semifinal (pool 1/2 winners meet in the QF, 4/5 in round one).
- Tie on all criteria for a place that matters → ipponshobu; two ties at once → replay the pool.
- Team: more bout wins → more ippons → daihyosen.
- Small categories (owner, 2026-11-07): 3 entries → no KO; options are round robin, move all to a stronger category, or cancel the category. 4 entries → round robin or direct KO. Implemented as `smallCategoryFormats()` in `draw.js`; Drawings page offers round robin, "move all" (RPC `move_category_entries`, cancels the source) and cancel/restore (category status `cancelled`).
- KO templates must be editable per category (organizers adjust pairings for a specific draw).
